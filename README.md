# ЛУЧ v1.8

Голосовой ассистент для Arch Linux: распознавание речи, синтез голоса, локальные и
облачные LLM, управление компьютером и Android-телефоном, веб-интерфейс.

Версия 1.8 — результат полного аудита и переработки кода v1.7: устранены найденные
ошибки, добавлена обязательная аутентификация веб-API и подтверждение опасных команд.

---

## Что умеет

| Возможность | Модуль |
|---|---|
| Распознавание речи (faster-whisper локально или Google) | `main.py` |

## Установка

```bash
python -m venv ai_env
source ai_env/bin/activate

# torch/torchaudio для CUDA — из отдельного индекса
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu130

pip install -r requirements.txt
```

Требуется Python 3.14 (проверено на 3.14.6).

---

## Запуск

```bash
# ядро + веб-интерфейс
python main.py

# GUI-монитор (запускает ядро сам)
python gui_launcher.py
```

При первом запуске:

1. Ассистент попросит произнести длинную фразу — это эталон вашего голоса
   (голосовой пропуск). Файл: `my_voice_profile.wav`.
2. В `settings.json` будет сгенерирован `web_token` — **он выведется в консоль**.
   Введите его в веб-интерфейсе в панели CONFIG (поле `web_token`).

Веб-интерфейс: `http://<ip>:1337`, защищённый (нужен для микрофона в браузере):
`https://<ip>:1338`.

## Безопасность

Аутентификация веб-API **обязательна**. Все методы `/api/*`, кроме служебных,
требуют заголовок `X-Luch-Token`.

**Публичные маршруты** (без токена):

- `GET /` — страница интерфейса
- `/static/*` — статика
- `GET /api/health` — проверка живости, без секретов
- `/api/device/register|queue|result|ping|location` — телефон аутентифицируется
  собственным токеном устройства (`client_id` + `token`)
- `/api/voice` — принимает **либо** `X-Luch-Token` (браузер), **либо** пару
  `client_id` + `token` в query-параметрах (телефон, который веб-токена не знает)

**Всё остальное** — только с `X-Luch-Token`.

Дополнительно:

- Автодокументация FastAPI (`/docs`, `/openapi.json`) отключена.
- Токены сравниваются побайтово, константным по времени `hmac.compare_digest`.
- Секреты (`zen_api_key`, `api_key` провайдеров, `web_token`) никогда не
  возвращаются через API — вместо значения отдаётся `{hidden, set, length}`.
- Опасные команды (`terminal`, `lock_pc`) требуют подтверждения и по голосу,
  и через веб.

> `settings.json` и `memory.txt` содержат ключи в открытом виде и исключены из
> git через `.gitignore`. Не публикуйте их.

## Проверка

```bash
cd v1.8
../ai_env/bin/python tests/selftest.py     # веб-API
../ai_env/bin/python tests/smoke_core.py   # ядро без железа
```

- **`tests/selftest.py`** — поднимает веб-приложение через TestClient с заглушкой
  ядра (микрофон, Whisper и GPU не нужны) и проверяет аутентификацию, отсутствие
  утечек секретов, обработку устройств и то, что `api_key` не принимается в URL.
- **`tests/smoke_core.py`** — подменяет микрофон, TTS и модели заглушками и
  реально создаёт `AIconsole`, после чего проверяет гейт опасных команд,
  разграничение веб/консоль, маскировку секретов и разбор документации команд.

Оба стенда не трогают железо и не мешают уже запущенному экземпляру ассистента.

## Конфигурация

Основные ключи `settings.json`:

| Ключ | Назначение |
|---|---|
| `web_token` | токен доступа к веб-API (генерируется автоматически) |
| `provider` | `ollama`, `zen` или id своего провайдера |
| `model` | модель Ollama |
| `ai_providers`, `ai_active` | список OpenAI-совместимых провайдеров |
| `whispermodel`, `stt_mode` | модель и режим распознавания речи |
| `tts_voice`, `tts_device`, `speed_ai_speak` | синтез речи |
| `micro_index` | индекс микрофона |
| `trigger_word` | слово-триггер обращения |
| `confirm_dangerous` | спрашивать подтверждение для опасных команд |

Файл пишется атомарно (`.tmp` + `replace`) с правами `0600`.

## Android

Исходники в `android/app/src/main/java/proekt/luch/app/`, готовый APK —
`android/LUCH-1.7.apk`. Телефон подключается к тому же веб-серверу и
регистрируется в `device_control.py`, после чего ассистент может звонить,
отправлять уведомления, включать фонарик и получать геопозицию.
