# ЛУЧ v1.8

Голосовой ассистент для Arch Linux: распознавание речи, синтез голоса, локальные и
облачные LLM, управление компьютером и Android-телефоном, веб-интерфейс.

Версия 1.8 — результат полного аудита и переработки кода v1.7: устранены найденные
ошибки и обязательная аутентификация веб-API. Подтверждения опасных команд нет:
команда выполняется сразу, как голосом, так и с сайта.

---

## Первый запуск

Модель проверки голоса весит ~90 МБ, поэтому в репозиторий она **не входит** —
приложение должно стартовать на любом компьютере без тяжёлых файлов в git.
Скачивается один раз:

```bash
python fetch_models.py
```

Скрипт берёт модель из релизов этого же репозитория, а если не вышло — с
HuggingFace и зеркала. Скачивать вручную не нужно.

Если `fetch_models.py` не справился (нет интернета), скачай архив вручную со
страницы релизов и распакуй в `pretrained_models/spkrec/`:

```
https://github.com/SUPERALEX93/luch-v1.8/releases
```

> Если модель недоступна, ЛУЧ **не падает**: он запустится и честно напишет,
> что голосовая проверка отключена и принимает любой голос. Остальная
> функциональность — текстовый режим, управление ПК и телефоном — работает.

## Установка

```bash
python -m venv ai_env
source ai_env/bin/activate

# torch/torchaudio для CUDA — из отдельного индекса
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu130

pip install -r requirements.txt
```

Требуется Python 3.14 (проверено на 3.14.6).

## Запуск

```bash
# ядро + веб-интерфейс
python main.py

# GUI-монитор (запускает ядро сам)
python gui_launcher.py
```

При первом запуске:

1. Ассистент попросит произнести длинную фразу — это эталон вашего голоса
   (голосовой пропуск). Файл: `my_voice_profile.wav`.
2. В `settings.json` генерируется `web_token`. При первом запуске он выводится
   в консоль. Если token уже создан при прошлом запуске, покажите его командой
   `/web_token` (в меню — «Показать web_token») и вставьте в веб-интерфейсе
   в панели CONFIG, поле `web_token`.

Веб-интерфейс: `http://<ip>:1337`, защищённый (нужен для микрофона в браузере):
`https://<ip>:1338`.

## Безопасность

Аутентификация веб-API **обязательна**. Все методы `/api/*`, кроме служебных,
требуют заголовок `X-Luch-Token`.

**Публичные маршруты** (без токена):

- `GET /` — страница интерфейса
- `/static/*` — статика
- `GET /api/health` — проверка живости, без секретов
- `/api/device/register|queue|result|ping|location` — телефон аутентифицируется
  собственным токеном устройства (`client_id` + `token`)
- `/api/voice` — принимает **либо** `X-Luch-Token` (браузер), **либо** пару
  `client_id` + `token` в query-параметрах (телефон, который веб-токена не знает)

**Всё остальное** — только с `X-Luch-Token`.

Дополнительно:

- Автодокументация FastAPI (`/docs`, `/openapi.json`) отключена.
- Токены сравниваются побайтово, константным по времени `hmac.compare_digest`.
- Секреты (`zen_api_key`, `api_key` провайдеров, `web_token`) никогда не
  возвращаются через API — вместо значения отдаётся `{hidden, set, length}`.
- Опасные команды (`terminal`, `lock_pc`) выполняются сразу — по голосу и с сайта.
  Действие необратимо: команда уходит в систему без дополнительного вопроса.

> `settings.json` и `memory.txt` содержат ключи в открытом виде и исключены из
> git через `.gitignore`. Не публикуйте их.

## Проверка

```bash
cd v1.8
../ai_env/bin/python tests/selftest.py          # веб-API внутри процесса
../ai_env/bin/python tests/smoke_core.py        # ядро без железа
../ai_env/bin/python tests/smoke_voice_path.py  # голосовой путь на синтетическом WAV
../ai_env/bin/python tests/live_server.py       # реальный HTTP-сервер
```

- **`tests/selftest.py`** — поднимает веб-приложение через TestClient с заглушкой
  ядра (микрофон, Whisper и GPU не нужны) и проверяет аутентификацию, отсутствие
  утечек секретов, обработку устройств и то, что `api_key` не принимается в URL.
- **`tests/smoke_core.py`** — подменяет микрофон, TTS и модели заглушками и
  реально создаёт `AIconsole`, после чего проверяет гейт опасных команд,
  разграничение веб/консоль, маскировку секретов и разбор документации команд.
- **`tests/smoke_voice_path.py`** — прогоняет `listen_user` на синтетическом WAV:
  отсечение триггер-слова, игнорирование фразы без обращения, отказ чужому
  голосу, пустое распознавание и отсутствие файла записи.
- **`tests/live_server.py`** — запускает НАСТОЯЩИЙ uvicorn на порту 13999 и ходит
  по нему по сети: middleware, отдача статики с подстановкой версии сборки,
  кэширование, регистрация устройства и корректная остановка.

Всего 132 проверки, все проходят на чистой копии репозитория. Стенды работают
на заглушках, не трогают рабочие файлы проекта (реестр устройств и эталон голоса
уводятся во временные файлы), не занимают порт 1337 и не мешают уже запущенному
экземпляру ассистента.

## Конфигурация

Основные ключи `settings.json`:

| Ключ | Назначение |
|---|---|
| `web_token` | токен доступа к веб-API (генерируется автоматически) |
| `provider` | `ollama`, `zen` или id своего провайдера |
| `model` | модель Ollama |
| `ai_providers`, `ai_active` | список OpenAI-совместимых провайдеров |
| `whispermodel`, `stt_mode` | модель и режим распознавания речи |
| `tts_voice`, `tts_device`, `speed_ai_speak` | синтез речи |
| `micro_index` | индекс микрофона |
| `trigger_word` | слово-триггер обращения (по умолчанию `луч`) |

Файл пишется атомарно (`.tmp` + `replace`) с правами `0600`.

## Android

Исходники в `android/app/src/main/java/proekt/luch/app/`, готовый APK —
`android/LUCH-1.8.apk`. Телефон подключается к тому же веб-серверу и
регистрируется в `device_control.py`, после чего ассистент может звонить,
отправлять уведомления, включать фонарик и получать геопозицию.

## Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| `RepositoryNotFoundError` / 401 при старте | не скачалась модель проверки голоса — `python fetch_models.py` |
| Ассистент не отвечает | не сработало слово-триггер (по умолчанию `луч`) — произнесите его в начале фразы |
| Реагирует на чужой голос | не записан эталон или отключена проверка — запишите его заново через меню (`Запись голоса`) |
| `Address already in use` | порт 1337 занят — закрой прошлый экземпляр или смени порт в `settings.py` |
| Не слышно синтеза речи | не выбран вывод — проверь `tts_device` в настройках |
| Веб-интерфейс не открывается с телефона | телефон и компьютер должны быть в одной сети, адрес указывается вида `http://192.168.1.10:1337` |

Проверить, что всё в порядке, можно без микрофона и без GPU:

```bash
../ai_env/bin/python tests/smoke_core.py
../ai_env/bin/python tests/smoke_voice_path.py
```
